Intelligence Store: Data Model

New tables for cumulative learning and insight delivery

Entity Relationships
staves (existing)
id
name
data_source_type
connection_config
is_active
1 —— has many —— *
data_profiles NEW
id: uuid
stave_id: fk → staves
tenant_id: str
domain_type: str
domain_context: json
schema_map: json
entity_roles: json
created_at: timestamp
updated_at: timestamp
1 per stave, updated over time
baseline_snapshots NEW
id: uuid
stave_id: fk → staves
tenant_id: str
snapshot_type: enum
  # auto_scan | daily | on_demand
table_metrics: json
  # {table: {row_count, null_rates,
  # distributions, freshness}}
column_stats: json
captured_at: timestamp
Many per stave, one per run
insight_reports NEW
id: uuid
stave_id: fk → staves
tenant_id: str
snapshot_id: fk → baseline_snapshots
report_type: enum
  # initial | daily | on_demand
health_score: int (0-100)
dimensions: json
  # [{name, score, trend, details}]
anomalies: json
  # [{description, severity, table}]
suggestions: json
  # [{action, reasoning, priority}]
summary: text
  # natural language for chat
checks_created: json
  # [clef_ids auto-created]
created_at: timestamp
Many per stave, one per analysis
Relationship Flow
stave → data_profile (1:1, updated in place)
stave → baseline_snapshots (1:many, time-series)
baseline_snapshot → insight_report (1:1, analysis of that snapshot)
insight_report → clefs (1:many, auto-created checks)

Tenant Isolation

Today (Single-Tenant)
tenant_id = "default"

Every row gets a tenant_id column but it's always "default". No overhead, just a column.
→
Future (Multi-Tenant)
tenant_id = org.id

All queries already filter by tenant_id. Just wire it to the org model when ready. Zero migration needed.
