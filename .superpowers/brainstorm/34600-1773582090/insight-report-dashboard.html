InsightReport Structure & Dashboard

What the AI produces and how the frontend consumes it

InsightReport Pydantic Model
class InsightReport(BaseModel):
    health_score: int  # 0-100
    report_type: Literal[
        "initial", "daily", "on_demand"
    ]

    # Scored business dimensions
    dimensions: list[Dimension]

    # Things that look wrong
    anomalies: list[Anomaly]

    # What the business should consider
    suggestions: list[Suggestion]

    # Natural language for chat
    summary: str
    key_findings: list[str]

    # Checks to auto-create
    checks_to_create: list[CheckSpec]

class Dimension(BaseModel):
    name: str  # "data_freshness"
    label: str  # "Data Freshness"
    score: int  # 0-100
    trend: Literal[
        "improving", "stable", "declining"
    ]
    delta: float | None  # vs last run
    details: str  # explanation

class Anomaly(BaseModel):
    severity: Literal[
        "low", "medium", "high", "critical"
    ]
    category: str  # "volume", "quality", etc
    table: str
    description: str
    evidence: str  # supporting data
    compared_to: str | None  # "7-day avg"

class Suggestion(BaseModel):
    priority: Literal[
        "low", "medium", "high"
    ]
    category: str  # "growth", "retention"
    action: str  # what to do
    reasoning: str  # why
    based_on: str  # evidence
Design Rationale
Structured + Natural language
Dimensions/anomalies/suggestions are structured for the dashboard. Summary + key_findings are natural language for chat.

Evidence-based
Every anomaly has evidence, every suggestion has based_on. The AI must show its work, not just assert.

Actionable
Suggestions have priority + category. checks_to_create are ready-to-persist ClefCreate specs.

Comparable
Dimensions have trend + delta so the dashboard can show direction arrows and sparklines.
