Cold Start: Without vs With Archetypes
Without Archetypes
Day 1: "I see 12 tables"
Day 3: "Orders table grows daily"
Day 7: "Weekend spikes detected"
Day 14: "This might be seasonal"
Day 30: "I understand this business"

~30 days to useful insights
With Archetypes
Day 1: "E-commerce detected. I already know:
  - Weekend spikes are normal
  - Watch for cart abandonment rates
  - Typical churn: 3-7%/month
  - Revenue seasonality expected"
Day 3: "Your churn is 8.2% — above typical range"

Useful insights from day 1

How Archetype Matching Works
1. Schema discovered
→
2. LLM matches against
    archetype signatures
→
3. Best match loaded
    (+ confidence score)
→
4. Archetype informs
    first-day analysis
→
5. Profile diverges as
    real data overrides
Archetypes are starting points, not constraints. The LLM may match "e-commerce" but then discover this business also has IoT sensor data (smart shelves). The profile adapts — archetype knowledge is a boost, not a cage. If no archetype matches well (confidence < 50%), the system falls back to generic exploration.

Archetype Storage

Shipped as YAML files, easy to extend

datametronome/podium/archetypes/ecommerce.yaml
name: e-commerce
description: Online retail, orders, products

signatures:
  required: [orders, products, customers]
  optional: [carts, payments, categories,
             reviews, shipping]

metrics:
  - name: average_order_value
    query_hint: "AVG(total) FROM orders"
    typical_range: [20, 200]
  - name: cart_abandonment_rate
    typical_range: [0.60, 0.80]

patterns:
  - weekend_order_spike
  - holiday_seasonality
  - payment_failure_baseline

suggested_checks:
  - type: freshness
    table: orders
    schedule: "0 * * * *"
  - type: row_count_anomaly
    table: orders
    schedule: "0 0 * * *"
Why YAML files?

✓ Easy to read and edit
✓ Ships with the package
✓ Users can add custom archetypes
✓ Version controlled with the code
✓ No database needed to bootstrap
