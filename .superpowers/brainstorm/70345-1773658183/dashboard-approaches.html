Dashboard: Datasource-Centric Approaches

Three ways to make the Intelligence Pulse aware of which datasource it's talking about. Click to select your preference.

A

Datasource Selector — single active context

A pill-based selector sits above the Intelligence Pulse. "All" is the default, but the user switches to a specific datasource and the entire Pulse refreshes to reflect that source only.

Pros

  • Familiar pattern (Grafana, Datadog)
  • Clean — one context at a time
  • Easy to add macrocategory grouping later

Cons

  • "All" view hides per-source identity
  • Requires click to see a specific source
B

Per-Datasource Cards — always-on overview ⭐ Recommended

Each datasource gets its own compact Intelligence card. The Pulse section becomes a scannable grid — you see everything at once, no selection needed. Anomalies and suggestions are labelled by source by definition.

Pros

  • Zero ambiguity — every signal is labelled
  • Instant at-a-glance health across all sources
  • Scales well: 2–8 sources stay readable
  • Minimal backend change (already per-stave)

Cons

  • More vertical space than the current layout
  • Gets crowded beyond ~6 sources
C

Sidebar + Detail Panel — deep focus mode

A persistent left sidebar lists all datasources with a health indicator dot. Clicking one loads a full-width intelligence panel for that source. A "Summary" entry at the top shows the aggregated view.

Pros

  • Deep focus on one source at a time
  • Great for power users with many sources

Cons

  • Requires navigation — no instant overview
  • More complex to implement (routing/state)
  • Dashboard feels like a separate page, not a summary

My recommendation: B. The data is already per-stave on the backend — the dashboard just needs to stop aggregating it. Per-source cards require minimal API change, give instant overview, and every anomaly/suggestion is naturally labelled by source. Option A is a good fallback if the number of sources grows large (>6).
